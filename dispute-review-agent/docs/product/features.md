# Driver–Rider Dispute Review Agent — Product Features

## Core Positioning

An AI-powered dispute review system for Ryde, the Singapore ride-hailing platform. It uses large language models to automatically analyse both parties' statements, cross-validate evidence, and match platform rules, producing structured ruling recommendations with confidence scores.

## Feature List

### 1. Dispute Dashboard
- **Case statistics overview**: four core metric cards — total cases, pending review, under review, and resolved
- **Case list table**: shows all dispute cases with case number, title, type, priority, status, and creation time
- **Quick actions**: one-click navigation to case detail from each row; a top-bar button to submit a new case quickly

### 2. Case Submission
- **Case information**: title, dispute type (route deviation / no-show charge / property damage / safety accident), priority (low / medium / high / urgent)
- **Driver information**: name, ID, historical rating, incident statement
- **Passenger information**: name, account, historical rating, incident statement
- **Trip details**: pickup and drop-off locations, pickup and drop-off times, fare, distance, vehicle model, licence plate
- **Evidence management**: evidence description plus a dynamic list of evidence items that can be added or removed
- **Form validation**: front-end required-field checks + back-end Zod schema dual validation

### 3. AI Agent Review
- **One-click review trigger**: launch the AI Agent automated analysis on a pending case
- **Review loading state**: displays key step prompts while the AI is analysing
- **Structured review report**:
  - **Ruling recommendation**: support driver / support passenger / shared responsibility / inconclusive
  - **Confidence score**: 0–100 with a colour-graded progress bar
  - **Case summary**: a one-sentence summary generated by the AI
  - **Key issues**: a list of identified core disputes
  - **Driver-side analysis**: the driver's position and credibility assessment
  - **Passenger-side analysis**: the passenger's position and credibility assessment
  - **Evidence analysis**: assessment of how the evidence supports each party's claims
  - **Applicable rules**: matched Ryde platform policies and rules
  - **Ruling reasoning**: detailed explanation of the recommendation
  - **Confidence reasoning**: analysis of how the score was derived
  - **Suggested actions**: a list of specific follow-up handling recommendations

### 4. Case Detail
- **Case header**: number, status badge, priority badge, type badge, creation time
- **Side-by-side comparison**: driver and passenger information cards displayed next to each other
- **Trip information**: structured display of the complete trip data
- **Evidence information**: evidence description and evidence item list
- **AI review report**: the full structured analysis report

### 5. Evidence Knowledge Base and Intelligent Q&A
- **Evidence upload**: supports PDF, text (txt/md/csv/json), screenshots and photos; can be linked to a specific case or stored as global material (e.g. platform policies, driver handbook)
- **Automatic parsing**: PDF text extracted per page; screenshots/photos processed through OCR for English and Chinese text (optional vision model to generate image descriptions)
- **Internal company records**: dispute tickets, trips (GPS traces, chat logs, app events), and passenger/driver profiles pulled from internal APIs (currently mock interfaces)
- **Vector retrieval**: text is chunked and embedded into pgvector for semantic similarity search, filterable by case and material type
- **Intelligent Q&A**: enter a question → retrieve relevant evidence → a local LLM answers based on the evidence, with sources cited as [1][2]
- **Deduplication and retry**: duplicate files uploaded for the same case are automatically deduplicated; failed files can be reprocessed with one click

## Technical Architecture
- **Front-end**: React 19 + Vite + TanStack Query + shadcn/ui + Tailwind CSS 4
- **Back-end**: Express + TypeScript + Zod validation
- **Human intervention**: a reviewer can manually decide any case at any time (regardless of whether the AI has reviewed it or escalated it); the decision can be modified or withdrawn. A human decision takes priority over the AI and is not overturned by a re-review
- **Precedent learning**: human decisions flagged as "use as precedent" are saved to the precedent store; the AI Judge consults the 3 most recent same-type precedents to calibrate its standards when reviewing similar disputes (they are not treated as evidence). The precedent page allows viewing and deletion
- **Judge checklist**: before ruling, the Judge must answer every checklist item for the dispute type (e.g. no-show: arrival and scheduled time, wait start, wait duration and threshold, contact records), marking source conflicts
- **AI review**: three agents (passenger advocate, driver advocate, Judge); defaults to the Google Gemini free tier (gemini-3.8-flash, with automatic fallback to gemini-3.1-flash-lite, etc.), or Tencent TokenHub
- **Knowledge base** (all open-source, free, locally hosted): PostgreSQL + pgvector (database and vector search), Ollama (model serving), bge-m3 (embedding model), Qwen2.5 (Q&A model), unpdf (PDF parsing), tesseract.js (OCR)
- **Design style**: professional dark-blue sidebar + light main content area, conveying trust and authority
